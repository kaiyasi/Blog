# Mascot API

The mascot speech bubble is generated by a server-side Astro endpoint. Provider
credentials are read only by the Node server and are never included in browser
JavaScript.

## Configuration priority

1. Direct environment variables
2. Codex config (default)
3. OpenCode config

### Direct environment variables

```bash
AI_BASE_URL=https://ai.kot.gg/v1
AI_MODEL=nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free
AI_API_KEY=replace-with-server-secret
AI_MASCOT_REASONING_EFFORT=low
AI_TRANSLATION_MODEL=nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free
AI_REASONING_EFFORT=low
```

`AI_HTTP_HEADERS` accepts a JSON object when a provider needs custom headers.
The older `MASCOT_AI_*` names remain supported as aliases.
Mascot bubbles default to `low` reasoning even when the imported Codex config
uses `xhigh`; set `AI_MASCOT_REASONING_EFFORT` only when a provider needs a
different value.

### Codex format

By default the server reads `~/.codex/config.toml` and
`~/.codex/auth.json`. Override their locations with
`AI_CONFIG_PATH` and `AI_AUTH_PATH`.

The selected `model_provider`, `model`, `model_reasoning_effort`, provider
`base_url`, `wire_api`, `requires_openai_auth`, `http_headers`, `env_key`, and
`env_http_headers` fields are supported. The provider must use the Responses
wire API.

### OpenCode format

The server checks `./opencode.json` and then
`~/.config/opencode/opencode.json`. Set `AI_OPENCODE_PATH` to use a
different file, and set `AI_CONFIG_FORMAT=opencode` to prefer this
format over Codex.

The `provider.<id>.options.baseURL`, `apiKey`, `headers`, and model definitions
are supported. Use `AI_PROVIDER` to select a provider other than
`openai`.

## Runtime notes

- Config paths belong to the operating-system account running the deployed
  Node server, not to a site visitor.
- Production deployments should inject credentials through secret environment
  variables or a server-only mounted config file.
- The endpoint uses `store: false`, validates same-origin input, limits request
  frequency, and never returns provider errors or credentials to the browser.
- Clicking, rapid clicking, returning to the mascot, page position, local time,
  character, and outfit scene are sent as bounded context. No dialogue is
  stored in the frontend source.
- Mascot dialogue and incremental article translation share the same provider
  and key. Translation can use a separate model through `AI_TRANSLATION_MODEL`.
